## 一、这批文件是什么

选定 15 家公司**最近两年的定期报告全文 PDF**，每家公司 4 期，共 **60 份，148.6 MB**。

| 报告期 | 说明 | 发布时点（约） |
|--------|------|----------------|
| 2024年年度报告 | 2024 全年 | 2025-03 ~ 2025-04 |
| 2025年半年度报告 | 2025 上半年 | 2025-08 |
| 2025年年度报告 | 2025 全年 | 2026-03 ~ 2026-04 |
| 2026年半年度报告 | 2026 上半年 | 2026-08 |

**为什么是这 4 期**：今天 2026-09-29，2026 年年度报告还没出。要覆盖「最近 1-2 年」
的完整年度 + 中期，就是这 4 期。（用户在 2026-09-29 明确选定了这个范围。）

```
data/raw/
  000636.SZ_风华高科/
    2024年年度报告.pdf        3.9 MB / 213 页
    2025年半年度报告.pdf      1.6 MB / 180 页

    2026年半年度报告.pdf      1.1 MB / 180 页
  002138.SZ_顺络电子/
    2024年年度报告.pdf        3.4 MB / 218 页
    ...
  603678.SH_火炬电子/
    ...
```

- 文件夹名：`<股票代码带后缀>_<公司名>`，如 `600563.SH_法拉电子`。
  带后缀是为了**一眼看出交易所**，不用记代码段。
- 文件名：`<年份>年<年度报告|半年度报告>.pdf`。年份在前，方便字典序排序。
- **raw 里的 PDF 一律不手工编辑、不重命名、不改内容。**
  下载清单里记了每份的 md5，改动过就对不上了。

## 三、数据来源

| 项 | 说明 |
|----|------|
| 公告来源 | 东方财富公告接口 `np-anotice-stock.eastmoney.com/api/security/ann` |
| PDF 直链 | 东方财富 `np-cnotice-stock.eastmoney.com/api/content/ann` 的 `attach_url` 字段 |
| PDF 托管 | `pdf.dfcfw.com` |
| 抓取日期 | 2026-09-29 |
| 密钥 | 不需要 |

**东财是什么角色**：它是**转载方**，不是原始披露方。定期报告的法定披露渠道是
**巨潮资讯网（深市）／上交所官网（沪市）**。东财的 PDF 是转载件。

本项目用东财的原因：项目 01 实测巨潮接口返回空（见 01 的方法卡与工作地图），
而东财接口可用、无需密钥。**如果对来源权威性有更高要求，应当拿交易所／巨潮的版本核对。**

## 四、下载清单（含出处可追溯）

`data/clean/定期报告_下载清单.csv`，60 行，一份一行。

| 字段 | 含义（大白话） |
|------|----------------|
| `股票代码` | 如 `000636.SZ`，带交易所后缀 |
| `公司名` | 股票简称 |
| `报告期` | 如 `2025年年度报告` |
| `公告日期` | 这份报告是哪天公告的 |
| `art_code` | 东财的公告编号，凭它能在东财定位到原始公告页 |
| `公告标题` | 东财返回的完整标题（保留原始写法，没做清洗） |
| `PDF链接` | 实际下载用的直链 |
| `本地文件` | 相对项目根目录的路径 |
| `字节数` | 文件大小 |
| `md5` | 校验和，用来判断文件有没有被改动过 |
| `下载日期` | 2026-09-29 |

**回溯方式**：拿 `art_code` 拼
`https://data.eastmoney.com/notices/detail/<6位代码>/<art_code>.html`
就能打开原始公告页，核对 PDF 是否对得上。

## 五、核验结论（2026-09-29）

跑 `scripts/verify_reports.py`，两层都通过。完整输出见
`logs/verify_reports_2026-09-29.txt`。

### 结构层

- **60/60 通过**：都是有效 PDF（`%PDF` 魔数），字节数和 md5 与下载清单一致。
- **页数 102 ~ 246 页，中位 179 页**，没有异常小的文件（不像下载中断或错误页）。
- **各公司 2025 年报都比 2025 半年报厚**，符合预期，说明没张冠李戴。
- 60 份里有 **13 份**能读出 PDF 内部 `/Title` 元数据，其中 9 份标题里的年份
  与报告期一致；另外 4 份的元数据标题只是章节名，不含年份，无法据此比对。

### 内容层（装了 PyMuPDF 之后补做的）

- **文本层：60/60 都有**，字/页中位 **904 字**，远超方法卡的扫描件阈值（< 10 字/页）。
  → **这批文件都不需要走 OCR**，方法卡的第二步用不上。
- **身份核对：60/60 通过** —— 每份全文里都能找到对应的股票代码、公司简称、年份、报告类型。
  这是「有没有下错公司、错年份」的正面证据。

### ⚠ 一个反直觉的坑：封面格式各家不同

核验时一开始只查**封面**（前 2 页），结果报出 40 条问题，全是误报。实际是：

- 法拉电子的封面写「公司代码：600563 / 公司简称：法拉电子」
- **三环集团、达利凯普、麦捷科技等的封面只写工商全称**
  （如「潮州三环（集团）股份有限公司」），**既没有 6 位代码也没有简称**

统计：**只有 20/60 份封面写了股票代码，41/60 份封面写了简称。**
但**年份和报告类型是 60/60 都在封面上**。

所以身份核对**必须搜全文**（第二节「公司简介」里有代码和简称），
拿封面当依据会大面积误报。改脚本时别踩回去。

## 六、抓取时的坑（改脚本前必读）

### 1. 标题前缀不统一 —— 差点整家漏掉

- 风华高科：`风华高科:2025年年度报告`（公司名后**有**冒号）
- 法拉电子：`法拉电子2025年年度报告`（公司名后**没有**冒号）

一开始按冒号切前缀来取核心标题，结果**法拉电子 0 命中** —— 整家公司静默漏掉。
改成从标题**尾部**用正则锚定 `(\d{4})年(年度报告|半年度报告)$` 才对。

教训：**只测一家公司就开跑，会漏。** 深市沪市创业板各挑一家试。

### 2. 接口的 `stock_list` 只认 6 位纯代码

传 `000636.SZ` 会**静默返回 0 条**，不报错。所以脚本里先 `split(".")[0]`。
现在列表返回 0 条会**明确告警**，不再悄悄当成「这家公司没有报告」。

### 3. `f_node=1` 是「定期报告」分类

用它把公告范围缩小，一页 100 条就能覆盖两年，不用狂翻页。

### 4. 要排除的近似条目

`2025年半年度报告摘要`（摘要不是全文）、`2025年半年度财务报告`（另一份文件）、
`年度报告（更新后）`、`关于…年度报告的补充公告` 等。
脚本把**所有**含「年度报告」字样但没被选中的条目记进
`logs/fetch_reports_skipped_<日期>.csv`，方便回头核对没误杀。
2026-09-29 共 377 条，人工过了一遍，无目标期被误排除。

## 七、处理这批 PDF 的前置条件

- **PyMuPDF 1.28.2 已安装**（2026-09-29 装，走清华源）。
  这是 `methods/方法卡_年报提取.md` 指定的首选提取工具。
- **导入时用 `import pymupdf`，不要用 `import fitz`。**
  `fitz` 这个名字在 1.28 里已标记为 deprecated，会打警告，将来会被移除。
- 本机 pip 的用法见下（`pip` 不在 PATH，且官方源超时）：

```bash
python -m pip install <包名> --timeout 120 --retries 5 \
  -i https://pypi.tuna.tsinghua.edu.cn/simple
```

- **这批文件都有文本层，不需要 OCR。** 所以方法卡里 OCR 和视觉模型那两步
  在这批材料上大概率用不上 —— 除非将来遇到扫描件版本的报告。
